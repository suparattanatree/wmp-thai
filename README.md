# wmp-ไทย

ตรวจจับตอนพิมพ์ลืมสลับภาษา แล้วแก้ให้เองทันทีบน macOS 26 (Apple Silicon)

พิมพ์ `l;ylfu` ทั้งที่ตั้งใจพิมพ์ `สวัสดี` มันจะแก้ให้เป็น `สวัสดี` พร้อมสลับ input source ให้
ทำงานเงียบ ๆ ไม่หน่วงการพิมพ์

แก้ให้ 3 จังหวะ (เปิด/ปิดแยกกันได้):

- **กลางคำ** พอมั่นใจแล้วสลับให้เลยระหว่างพิมพ์ ปกติจับได้ภายใน 3-5 ตัว
  เช่นพิมพ์ `l;yl` มันจะแก้เป็น `สวัส` แล้วสลับแป้นเป็นไทย ที่เหลือพิมพ์ต่อได้เลย
- **พอหยุดพิมพ์** หยุดนิ่งเกินเวลาที่ตั้งไว้ (ค่าเริ่มต้น 400 ms ปรับได้ 150-2000 ms หรือปิด) ก็แก้ให้เลย
  ไม่ต้องเคาะ space ใช้ทั้งเกณฑ์คำเต็มและเกณฑ์กลางคำ
- **ตอนเคาะ space** ตัวสุดท้ายที่รับคำที่สองจังหวะแรกยังไม่มั่นใจพอ

## ทำงานยังไง

1. ดัก keystroke ด้วย CGEventTap แบบ **listen-only** คือมองอย่างเดียว ดักไม่ได้ หน่วงไม่ได้
   ต่อให้แอปนี้ค้าง การพิมพ์ก็ไม่สะดุด
2. เก็บคำที่กำลังพิมพ์ไว้เป็น "ปุ่มที่กด" ไม่ใช่ "ตัวอักษรที่ได้"
   เลยแปลงกลับไปอีกเลย์เอาต์ได้ตรงเป๊ะ ไม่ต้องเดา
3. พอเคาะ space / enter / tab ก็ให้คะแนน 2 ทาง: ที่พิมพ์ไปกับที่ควรจะเป็น
4. ถ้าอีกฝั่งชนะขาดค่อยแก้ ถ้าก้ำกึ่งคือไม่แตะ

ตารางคีย์บอร์ดอ่านจากระบบจริง (`TISInputSource` + `UCKeyTranslate`) ไม่ได้ hardcode
เปลี่ยนไปใช้ Thai Pattachote หรือ ABC/US แบบไหนก็ยังตรง

### ตัดสินยังไงว่าอันไหนคือภาษาอะไร

- **ไทย**: กฎการสะกดไทย (สระ/วรรณยุกต์ลอยหน้าคำ วรรณยุกต์ซ้อน ฯลฯ) + ตัดคำด้วย ICU + คลังคำ 40,000 คำ
  อังกฤษที่พิมพ์บนเลย์เอาต์ไทยมักผิดกฎสะกดตั้งแต่ตัวแรก เช่น `hello` ออกมาเป็น `้ำสสน` ที่ขึ้นต้นด้วยไม้โท
- **อังกฤษ**: `/usr/share/dict/words` + NSSpellChecker และคลังคำที่ "คนพิมพ์จริง" อีกชุด (16,000 คำ
  สกัดจากข้อความอังกฤษใน en.lproj ของระบบ) ใช้ตอนที่หลักฐานฝั่งไทยไม่ชัด เพราะ dict/words มีคำอย่าง
  "meso" "miim" ที่ไม่มีใครพิมพ์ปนอยู่เยอะ
- **เดาให้ถ้าอ่านไม่ออก** (เปิดไว้เป็นค่าเริ่มต้น) ถ้าสิ่งที่พิมพ์ออกมา "อ่านไม่ออก" ในภาษานั้นจริง ๆ
  (ไทยผิดกฎสะกด / อังกฤษไม่มีสระ พยัญชนะติดกันเกิน 4 ตัว) และอีกฝั่งอ่านออก ก็แก้ให้เลยโดยไม่ต้องมีในคลังคำ
  อันนี้คือตัวที่ช่วยพวกชื่อเฉพาะกับคำแสลง เช่น `emma` `github` `docker` `kubernetes` `gonna` `จุงเบย`
- คำสั้นกว่า 3 ตัวไม่แก้ คำยาวเกิน 40 ตัวไม่แก้ (พวก token/URL)
- ถ้าข้อความไทยสะกดถูกกฎและมีคำไทยจริงอยู่ในนั้น จะไม่แปลงทิ้ง แม้ฝั่งอังกฤษจะดูดีกว่า

### ตอนสลับกลางคำใช้เกณฑ์แยกอีกชุด (เข้มกว่า)

เพราะสลับผิดกลางคำกวนกว่าแก้ผิดตอนจบคำ เลยต้องมีหลักฐานชัดก่อน:

- ฝั่งที่แปลงแล้วต้องเป็น "ต้นคำจริง" ของคำในคลัง ไม่ใช่แค่สะกดได้
- ฝั่งที่พิมพ์อยู่ต้องไม่ใช่ต้นคำอังกฤษที่เป็นไปได้
- ต้องมีร่องรอยว่าพิมพ์ผิดแป้น เช่นมีสัญลักษณ์/ตัวเลข/ตัวใหญ่โผล่กลางคำ (`l;yl`, `-v[`)
  หรือแปลงแล้วได้คำเต็มไปเลย
- ถ้าข้อความไทยที่พิมพ์อยู่มีคำไทยจริงซ่อนอยู่ (เช่น `ทำหน` ที่กำลังจะเป็น `ทำหน้าที่`) จะไม่แตะ
- สลับได้ครั้งเดียวต่อหนึ่งคำ

เช็คได้เองว่าตัดสินถูกไหม:

```bash
swift run wmp --selftest
```

ดูคะแนนของข้อความเดี่ยว ๆ:

```bash
swift run wmp --score "ยฟหหไนพก"
```

ดูผลแบบเดียวกับหน้า "ลองดู" จากเทอร์มินัล:

```bash
swift run wmp --try "l;ylfu8iy["
```

หรือใส่คำที่ตั้งใจพิมพ์ แล้วให้มันจำลองการพิมพ์ผิดแป้นเองด้วยตารางคีย์จริง:

```bash
swift run wmp --typo "สวัสดี github จุงเบย"
```

เปิดเฉพาะหน้าต่างตั้งค่าเพื่อดู UI (ไม่แตะคีย์บอร์ด ไม่ขอสิทธิ์):

```bash
swift run wmp --preview
```

## ติดตั้ง

```bash
cd ~/Developments/wmp-ไทย && ./build_app.sh && mv wmp-ไทย.app /Applications/ && open /Applications/wmp-ไทย.app
```

จากนั้นเปิดสิทธิ์ Accessibility ให้ (System Settings > Privacy & Security > Accessibility)
แอปจะเริ่มทำงานเองทันทีที่ได้สิทธิ์ ไม่ต้องเปิดใหม่ (มันเฝ้าดูสถานะอยู่) ดูสถานะได้ในหน้าต่างตั้งค่า

`build_app.sh` จะเซ็นด้วยใบรับรองในเครื่องอัตโนมัติ (เลือก Developer ID ก่อน ถ้าไม่มีใช้ Apple Development)
ซึ่งทำให้แอปมีตัวตนคงที่ สิทธิ์ Accessibility เลยอยู่ข้ามการ build ใหม่ ถ้าไม่มีใบรับรองเลยจะถอยไปเซ็นแบบ ad-hoc
ซึ่งต้องกดให้สิทธิ์ใหม่ทุกครั้งที่ build

## แจกจ่าย

**Mac App Store: ไปไม่ได้** แอปบนสโตร์ต้องอยู่ใน sandbox แต่ตัวนี้ต้องดักคีย์บอร์ดทั้งระบบ
(CGEventTap + Accessibility) กับอ่านคลังคำจาก /System/Library ซึ่ง sandbox ปิดทั้งคู่
เครื่องมือแนวเดียวกัน (Karabiner, Keyboard Maestro, TextExpander, Alfred) ก็แจกนอกสโตร์กันหมด

**ทางที่ไปได้: Developer ID + notarize** แจกเป็น DMG ให้ใครโหลดไปติดตั้งก็ได้ ไม่ติด Gatekeeper

```bash
./package_dmg.sh
```

ต้องเตรียมก่อนครั้งเดียว: ใบรับรอง Developer ID Application กับ credential ของ notarytool
(รายละเอียดอยู่หัวไฟล์ `package_dmg.sh`)

ถ้าจะให้เปิดเองตอน login ก็ติ๊ก "Open at login" ในเมนู

## ตั้งค่า

เมนูบาร์ > `Settings...` หน้าต่างเป็น sidebar + form แบบเดียวกับ System Settings ของ macOS 26

- **ทั่วไป** เปิด/ปิด, แก้อัตโนมัติหรือแค่ตรวจจับ, **ทิศทางที่แก้** (ทั้งสองทาง / ABC → ก ข ค / ก ข ค → ABC),
  สลับกลางคำ, สลับแป้นหลังแก้, เปิดเองตอน login
- **ความไว** เลือก 3 แบบ: ระวังตัว / สมดุล / ไว ส่วนสไลเดอร์ดิบ ๆ ซ่อนไว้ใน "ปรับเอง"
  ค่าที่ปรับมีผลทันที ไม่ต้องรีสตาร์ท
- **ยกเว้นแอป** เลือกแอปจาก /Applications ที่ไม่อยากให้ยุ่งด้วยเลย
- **ลองดู** วางข้อความลงไปแล้วดูว่าเกณฑ์ตอนนี้จะทำอะไรกับแต่ละคำ (สลับกลางคำที่ตัวที่เท่าไหร่ / แก้ตอนเคาะ space / ไม่แตะ)
  พร้อมรายการที่แก้ไปจริงล่าสุด ใช้จูนความไวได้โดยไม่ต้องเดา

ในเมนูบาร์ยังมีสวิตช์ที่ใช้บ่อยให้กดเร็ว ๆ อยู่เหมือนเดิม

ในช่อง secure input (ช่องรหัสผ่าน) แอปจะไม่อ่านอะไรเลยอยู่แล้ว

## คลังคำต้องใหญ่แค่ไหน

วัดด้วย `swift run wmp --sweep` (ตัดคลังคำไทยเหลือ N คำที่พบบ่อยที่สุด แล้ววัดกับคำไทย 3,300 คำที่คนพิมพ์บ่อย):

| ขนาดคลัง | ครอบคลุมข้อความ | จับคำผิดภาษาได้ | แก้คำถูกผิดพลาด |
|---|---|---|---|
| 0 | 0% | 53.7% | 0.24% |
| 500 | 77.3% | 73.3% | 0.18% |
| 1,000 | 88.1% | 79.8% | 0.18% |
| 2,000 | 94.8% | 87.7% | 0.06% |
| **5,000** | **98.9%** | **99.4%** | **0.00%** |
| 10,000+ | 100% | 99.4% | 0.00% |

- **5,000 คำคือจุดพอ** หลังจากนั้นเพิ่มไปก็ไม่ได้อะไรเพิ่ม
- ที่ 0 คำยังจับได้ครึ่งหนึ่ง เพราะกฎ "อ่านไม่ออก" ไม่ต้องใช้คลังคำ
- คลังใหญ่ยังช่วยอีกทาง: ยิ่งใหญ่ยิ่ง**แก้คำที่ถูกอยู่แล้วผิดพลาดน้อยลง** (0.24% → 0%)
  เพราะรู้จักคำไทยจริงมากขึ้นก็ยิ่งรู้ว่าเมื่อไหร่ไม่ควรแตะ

ของจริงที่สร้างได้ในเครื่องคือ **ไทย ~40,000 / อังกฤษ ~16,000** ซึ่งเกินจุดพอไปเยอะแล้ว
คลังที่เราดูแลเองจึงไม่ต้องใหญ่ มีไว้เติมเฉพาะคำที่หลุด (ศัพท์เครื่องมือ แสลง ชื่อแบรนด์)

## คลังคำ 3 ชั้น

| ชั้น | มาจากไหน | เก็บที่ไหน | อัปเดตยังไง |
|---|---|---|---|
| จากเครื่องนี้ | ข้อความ th.lproj/en.lproj ของทุกแอปในเครื่อง (ดิกชันนารีของ macOS เป็นตัวเลือกที่ปิดไว้) | `~/Library/Application Support/wmp-thai/` | สร้างเองตอนเปิดครั้งแรก (~28 วิ) กดสร้างใหม่ได้ในหน้าคลังคำ |
| ที่มากับแอป | `Sources/WmpCore/Resources/curated_*.txt` ที่เราดูแลเอง | ในตัวแอป | แก้ไฟล์ใน repo แล้วปล่อยเวอร์ชันใหม่ |
| ที่ผู้ใช้เพิ่มเอง | หน้าคลังคำ หรือกด ⌃⌥Z ย้อนการแก้ | `~/Library/Application Support/wmp-thai/user_words.txt` | ผู้ใช้เพิ่ม/ลบเองได้ตลอด |

ชั้นแรกไม่ถูกแจกจ่ายไปกับแอปเพราะสกัดมาจากข้อมูลของ Apple ส่วนชั้นที่สองเป็นของเราจึงแจกได้

### เรื่องสิทธิ์ของข้อมูล

ตัวที่สร้างเป็นค่าเริ่มต้นอ่านเฉพาะไฟล์ `.strings` ที่เป็นข้อความหน้าจอของแอปต่าง ๆ แล้วนับความถี่คำ
ผลลัพธ์เป็นสถิติที่อยู่ในเครื่องคนใช้ ไม่ถูกส่งออกไปไหน

ส่วนการอ่าน **ดิกชันนารีไทยของ macOS** ต้องแกะรูปแบบไฟล์ที่ Apple ไม่ได้เปิดสเปก และเนื้อหาในนั้น
Apple ซื้อสิทธิ์มาจากสำนักพิมพ์อีกที เลยเป็นจุดที่คลุมเครือที่สุด **จึงตั้งเป็นตัวเลือกที่ปิดไว้**
(เปิดได้เองในหน้าคลังคำ ได้คำเพิ่มราว 36,000 คำ)

ปิดไว้แล้วคุณภาพแทบไม่ต่าง วัดแล้ว: คำทางการอย่าง `ทฤษฎี` `ปรัชญา` `อัญมณี` `กงสุล`
ยังจับได้ครบเพราะกฎ "อ่านไม่ออก" ไม่ต้องพึ่งคลังคำ และคลังที่ได้ (ไทย ~7,800 คำ) ก็เกินจุดพอที่ 5,000 อยู่แล้ว
กด ⌃⌥Z ย้อนการแก้คำไหน คำนั้นจะถูกจำไว้ให้อัตโนมัติ ครั้งหน้าจะไม่โดนแก้อีก

สร้างคลังคำใหม่จากเทอร์มินัลก็ได้:

```bash
swift run corpusgen
```

## ข้อจำกัดที่รู้อยู่

- แก้ทีละคำ ไม่ได้ย้อนแก้ทั้งประโยคที่พิมพ์ไปแล้ว
- `⌃⌥Z` ย้อนได้เฉพาะการแก้ครั้งล่าสุด ถ้าสลับกลางคำแล้วพิมพ์ต่อ การย้อนจะได้แค่ส่วนที่มันแก้
- ตอนลบ มันอ่านข้อความในช่องที่โฟกัสผ่าน Accessibility API แล้วลบทีละตัวจนพอดี
  เพราะ backspace หนึ่งครั้งลบไม่เท่ากันในแต่ละแอป (Cocoa ลบทีละตัว, Electron/Chromium ลบทั้งกลุ่มสระ+พยัญชนะ)
  ถ้าลบเกินมันจะพิมพ์ส่วนที่เกินคืนให้ ส่วนแอปที่อ่านค่าไม่ได้ (เทอร์มินัล ช่องรหัสผ่าน) จะถอยไปใช้การนับแทน
- รองรับคู่ไทย/อังกฤษเท่านั้น
- คลังคำมาจาก UI ของ macOS เป็นหลัก คำแสลงหรือคำใหม่ ๆ อาจไม่รู้จัก ผลคือ "ไม่แก้ให้" ซึ่งปลอดภัยกว่าแก้มั่ว
